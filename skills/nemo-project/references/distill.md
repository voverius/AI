# Distill

Read [lifecycle](lifecycle.md), [ownership](ownership.md), and [retention](retention.md)
if not already loaded.

1. **Select.** Identify the processed set: relevant inputs, findings, checkpoint material
   Choose owning subjects via ownership rules: reusable entity/domain facts vs tool-specific
   procedures. Read existing owners and needed source context. No owner in the mapped
   knowledge folder for a reusable finding → create one. A deliverable alone is not
   distillation. Leave unrelated or incompletely read inputs untouched
2. **Merge.** Extract what improves future work into the owning topic. Keep evidence and
   decision rationale. Provenance with claims (source identity or user decision/observation,
   plus supporting detail); keep that when discarding an input. Keep useful proposals and
   rejected approaches with status. Decision = intent; claim execution only with execution
   evidence. Contradictions: assess evidence and scope; supersede only when justified,
   else retain the conflict and what would resolve it. Recency alone is not truth. After
   knowledge changes: read back README, index, affected outputs and handovers. Strip task
   status from navigation; refresh editable results or mark stale; keep retained originals
3. **Index and clean.** Update owning index branch and incoming links when subjects or cues
   change; create the first index if absent. Every maintained topic reachable; README stays
   a role map. Before cleanup: check retained claims against cited sources; separate
   inference from source content. Confirm useful findings survive without duplication,
   uncertainty stays visible, deliverables match evidence. Move explicitly retained
   processed originals to `sources/` and repair links. Delete eligible inputs/intermediates
   only under retention rules; surviving knowledge must keep source identity and support
   for deleted originals

Clean resolved detail from handovers after preservation. Report unresolved processing or
conflicts briefly. Re-running with no new information should not change files.
Done: relevant knowledge is retrievable and supported (not: inbox empty).
