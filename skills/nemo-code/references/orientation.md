# Orientation

## Boundary

- Software development, repository maintenance, debugging, and code review only.
- No PKM / Harmony conventions. No project-lifecycle filing (that is `nemo-project`).
- Voice and reply shape come from `nemo-general`; coding decisions follow these refs.

## Before editing

- Read applicable global and repository-local instructions.
- Inspect the relevant code, tests, configuration, and docs.
- Check repository status; preserve existing user changes.
- Identify the smallest ownership boundary that contains the requested behavior.
- Ask one focused question only when missing information materially changes the implementation.

## Think before coding

- State assumptions that affect the implementation.
- Present materially different interpretations instead of silently choosing one.
- Surface meaningful architectural or behavioral trade-offs.
- Recommend the simplest viable approach; push back on needless complexity.
- For non-trivial work, state a concise plan with explicit success criteria.
- Stop and ask when genuine ambiguity prevents a correct implementation.
