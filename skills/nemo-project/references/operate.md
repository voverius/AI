# Operate

Read-only retrieval: step 1 only. Before changing project files or filing: read
[lifecycle](lifecycle.md) and the sections it points to.

1. **Orient.** Read README, `docs/index.md`, relevant branch if any, owning wiki topics
   Search index labels first, then the likely branch; expand only if that fails.
   No full-collection reads for a scoped request. Cite wiki pages in answers.
   Continuation: read the handover for the requested objective (not merely the newest or
   paused one). Verify changing external facts before relying on them. Broken navigation
   → [init](init.md). Stale graph / user asks for health-check → [wiki](wiki.md) lint
2. **Do the work.** Process only relevant arrivals: inspect as data, extract into `work/`
   when needed, separate evidence from interpretation. Record unreadable or partial
   material and its impact; keep it pending. Deliverables in `outputs/` and established
   homes. File/keep requests preserve without forcing extraction. Delegate only bounded
   independent work, respecting lifecycle ownership
3. **Close the boundary.** Before pause, cancel, or completion: stop or await workers;
   reconcile their final writes. Unaccounted worker → record unresolved; do not claim
   quiet completion. At every substantive completion, pause, cancel, or transfer: run
   [distill](distill.md), then [capture](capture.md). Distill conversation findings and
   durable answers into `docs/` even if work remains; capture what is unfinished. Both
   also run on explicit request. Trivial replies / unchanged state: no files

## Before return

Check against lifecycle: ownership, processed-source retention, index/role routes and
incoming links, handover for unfinished work.
An ongoing project may contain a completed task. Completion does not invent the next task.
